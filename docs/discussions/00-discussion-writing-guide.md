# Discussion Writing Guide

## Purpose

Use this guide when requirements are ambiguous and need structured clarification.

## When To Use

Create a discussion file when:

- raw PM notes or prototypes are incomplete
- multiple interpretations are plausible
- business rules are unclear
- developers would need to guess domain meaning

## Output

- open questions
- assumptions
- pending confirmations
- decisions that unblock synthesis

## Rule

Write down ambiguity explicitly. Do not resolve it by guessing in code.

Move resolved conclusions to `docs/requirements/`.

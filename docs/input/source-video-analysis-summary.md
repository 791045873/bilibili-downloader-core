# 视频内容总结 + 重点配图 — 原始需求讨论

## 目标

对已下载的 Bilibili 视频，基于字幕 + 视频画面，自动生成图文并茂的总结文档（Markdown）。

## 核心工作流

```
字幕.srt
  → LLM 分析字幕原文
    输出: {
      整体总结,
      关键段落列表: [
        { 段落主题, 字幕原文片段, 起始时间, 结束时间 },
        ...
      ]
    }

  → 对每个关键段落:
      时间窗 [from - 3, to + 3]
      从窗口起始第 0 秒开始，每秒截图一张（截图数量 = 窗口总秒数 + 1）

    → 该段落所有截图 + { 段落主题, 字幕原文片段 }
       LLM (多模态: 文本+图片) 选出最合适的一张或多张

    → 循环，得到所有段落的最佳配图

  → 组装 Markdown 文档:
    图片使用本地文件路径或云端存储桶 URL，禁止 Base64
```

## 关键细节

### 字幕分析（第一次 LLM 调用）
- 输入：完整的 SRT 字幕原文（纯文本）
- 模型：千问 3.6 Flash（纯文本处理）
- 输出结构：
  - 整体总结
  - 关键段落列表，每个段落包含：段落主题、对应的字幕原文片段、起始时间、结束时间
- 段落数量不限，由 LLM 根据内容自行决定

### 截图（ffmpeg）
- 时间窗：[关键段落起始时间 - 3s, 关键段落结束时间 + 3s]
- 从窗口起始第 0 秒开始截图，每秒 1 张
- 截图格式：JPEG
- 截图数量：窗口总秒数 + 1

### 截图筛选（第二次 LLM 调用，多模态）
- 输入：该段落的所有截图（图片）+ { 段落主题, 字幕原文片段 }（文本）
- 模型：千问 3.6 Flash（多模态，支持文本+图片输入）
- 输出：选出的合适截图列表（LLM 自行决定选出几张）

### 文档生成
- 格式：Markdown
- 图片引用方式：本地文件路径 或 云端存储桶 URL
- 禁止使用 Base64 内嵌图片

### 不纳入当前讨论范围的事项
- 用户交互方式（触发按钮、参数设置等）
- API Key 管理方式
- LLM 调用失败的重试/降级策略
- 文档的后续处理（分享、下载、删除等）

## 待确认的技术点

- 千问 3.6 Flash 的 API 接入方式（端点、鉴权方式）
- ffmpeg JPEG 截图的压缩质量参数
- 截图文件的存储位置约定
- 是否支持 0 个关键段落（视频无字幕 -> 跳过）
- 多 P 视频的处理方式（每个分 P 独立分析，还是合并分析）

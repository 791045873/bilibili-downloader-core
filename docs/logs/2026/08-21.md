# 2026-08-21

## LLM 并发调用限制（最多 2 个同时执行）

关联计划：`docs/plans/2026-08-21-llm-concurrency-limit-plan.md`；testing：`docs/testing/2026/08-21-llm-concurrency-limit-testing.md`。

### 变更

- `packages/adapters/src/llm/qwen-client.ts`：新增模块级 `AsyncLimiter`（Promise 信号量，默认上限 2，env `MAX_CONCURRENT_LLM_CALLS`），`multimodalChat` 入口包裹整个重试循环，最多 2 个 LLM 调用在途、超出排队等待。因闭包丢失属性收窄，`visionProxyUrl` 提取为局部常量。
- `packages/vision-proxy/qwen_vision_proxy.py`：`MAX_CONCURRENCY` 默认 `8` → `2`（兜底）；`do_GET` 的 `/healthz` 不再占用信号量槽位（Fix，避免并发满载时健康检查被 503 误判）。
- `packages/docker/docker-compose.yml`：server 服务新增 `MAX_CONCURRENT_LLM_CALLS:-2`；vision-proxy `QWEN_VISION_PROXY_MAX_CONCURRENCY:-2`。
- `packages/docker/.env.example` 与 `docs/architecture/2026-07-06-video-analysis-baseline.md`：并发默认值同步为 2，新增 `MAX_CONCURRENT_LLM_CALLS` 说明。

### 验证

- `pnpm typecheck` exit 0；`pnpm build` exit 0；Python `ast.parse` OK。
- 运行级 stub 冒烟：`{"peakInFlight":2,"totalReqs":4,"ok":4,"failed":0,"elapsedMs":720}`——并发钉死 2、第 3/4 排队且全部成功、无 503。
- 代理启动冒烟：`GET /healthz` 200 `{"status":"ok"}`；grep 确认 `_acquire_slot` 仅 `do_POST` 使用。
- `docker compose config --quiet` exit 0。

### 备注

- 排队语义在 Node 调用侧（编排归 Node，代理保持薄代理无业务语义）；Python 侧保留信号量作为兜底（默认 2）。部署保护区默认值变更由用户显式批准。

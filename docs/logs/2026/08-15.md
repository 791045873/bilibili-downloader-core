# Development Log - 2026-08-15

### 投稿视频列表项状态徽标与状态筛选（`docs/plans/2026-08-15-list-item-status-badges-and-filter.md`，已关闭）

- 来源：用户直接需求——投稿视频列表页每项展示「下载队列 / AI 分析队列」两类状态，并提供可分别筛选两类状态的表单。
- 状态映射：
  - 下载：`taskStatus === "downloading"` → 下载中；`=== "success"` → 已下载；其余（created/stopped/failed）不显示。
  - 分析：`summaryStatus` 为 `pending`/`analyzing` → 正在分析；`=== "completed"` → 分析完成；其余（failed/none）不显示。
- 数据源：`POST /api/tasks/check` 扩展——`DatabaseService.findTasksByBvidsAndCids` 增加 `LEFT JOIN ai_summary_task`（`UNIQUE (bvid,cid)` 保证单行）并返回 `summaryStatus`；新增字段非破坏性，`VideoDetail.tsx` 消费字段不受影响。
- 实现：`packages/server/src/database/database.service.ts`（checkTasks SQL）、`packages/frontend/src/api/index.ts`（checkTasks 返回类型）、`packages/frontend/src/pages/ParseResultList.tsx`（ListItem 增加 taskStatus/summaryStatus、四态徽标、下载/分析两个 Select 筛选、无匹配空态）。筛选为当前页客户端过滤。
- 冷回放自检发现并修复：下载筛选原逻辑用 `downloadFilter("downloaded") !== item.taskStatus("success")` 判断，导致「已下载」筛选永远为空——改为分别按 `"downloading"`/`"success"` 判定。
- 追加：筛选表单增加「未下载」（`taskStatus !== "success"`）与「未分析」（`summaryStatus !== "completed"`）两项，单文件小改动，typecheck 通过。
- 追加：下载/分析两个筛选项拆分为独立状态选项（下载：无任务/排队中/已停止/下载中/已下载/下载失败；分析：无记录/等待中/正在分析/分析完成/分析失败），均改为 `Select mode="multiple"` + `allowClear` 支持多选与取消，空选择即不筛选，移除「全部」选项。

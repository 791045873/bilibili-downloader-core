### Vision Proxy 服务健壮性（`docs/plans/2026-08-12-vision-proxy-robustness-plan.md`，已关闭）

- 分析：`docs/analysis/2026-08-12-vision-proxy-robustness-analysis.md`。单次请求异常不会杀死进程（`except Exception` + `ThreadingMixIn.process_request_thread` 独立 try/except/finally），"一次异常后永久不可调用"的真实来源是进程死亡 + `start-vision-proxy` 无自愈。
- Python 代理（`qwen_vision_proxy.py`）：请求 body 上限（`QWEN_VISION_PROXY_MAX_BODY_BYTES` 默认 16MB，超出 413 且不读 body）、缺失/非法 `Content-Length` → 400；socket 读写超时（`QWEN_VISION_PROXY_SOCKET_TIMEOUT` 默认 120s，handler `timeout` 类属性经 `StreamRequestHandler.setup` 生效）；并发上限（模块级 `BoundedSemaphore`，`QWEN_VISION_PROXY_MAX_CONCURRENCY` 默认 8，超限 503 并关闭连接）；`safe_send_json` 防 except 分支二次写异常逃逸；`address_string` 直接返回 IP 关闭反向 DNS；新增 `GET /healthz`。并发门控从 `handle()` 移入 `do_GET`/`do_POST`（修复 `parse_request` 前写响应导致 `requestline` 缺失的 `AttributeError`）。
- 启动自愈（`start-vision-proxy.mjs`）：指数退避自动重启（1s→2s→…上限 30s，稳定运行 ≥60s 重置），SIGINT/SIGTERM 优雅停止不重启（win32 下 Ctrl+C 作用于控制台进程组），`VISION_PROXY_NO_RESTART=1` 逃生门。
- Node 侧（`qwen-client.ts` + 两处 `getLlmConfig`）：`LlmConfig.visionProxyTimeoutMs` 读取 `QWEN_VISION_PROXY_TIMEOUT_MS`（默认 600000），`multimodalChat` 代理路径 `AbortController` + `setTimeout` 超时，默认值客户端兜底（`?? 600000`），覆盖 AI 总结 trigger 与手动分析两个调用面；仅作用于代理路径。
- 文档：架构基线环境变量清单与健壮性不变量更新；codebase-map Vision Proxy 行更新。
- 验证：`pnpm typecheck`、`pnpm build`、`node --check scripts/start-vision-proxy.mjs`、venv `python -m py_compile` 通过；运行级冒烟：/healthz 200、超大 body 413、非法/缺失 Content-Length 400、并发占满 503、异常后服务存活、杀进程自动拉起、Node 超时 1200ms 精确抛错。DashScope 真实成功链路（依赖有效 key + 本地媒体文件）留用户手动。

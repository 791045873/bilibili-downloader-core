- contract（e317ae0）：`User`（username 唯一 / password_hash / role / disabled_at?）、`UserSession`（token_hash 唯一 / user_id / expires_at）、`Conversation.userId?` + FK + 索引；`prisma:emit` 落地。
- 迁移（**本机产物，未提交**）：`prisma migration plan --from 20260917T0754_qa_chat_soft_delete --name worker_jobs_and_user_auth` 生成 `migrations/app/20260930T0753_worker_jobs_and_user_auth`，14 条 additive（user / user_session 两表 + conversation.user_id + 唯一约束/索引/FK，另补 worker_job / worker_heartbeat）。
  - `packages/server/migrations/` 被 `.gitignore` 排除（仓库注释：迁移图 authoring 提交内容待定），故该目录不随本次提交入库；schema 真源仍是 `contract.prisma` + emit 产物。
  - **为何指定 `--from`**：本机 `migrations/app/refs/db.json` 仍停在 `4daf8a58`（软删除迁移已规划但未对目标库 `db migrate`），默认规划会重复产出既有 `deleted_at` 操作；指定 from 后链路线性、无重叠。同时发现 Phase 2 收尾未生成迁移目录，本次一并补齐 worker 两表（仅本机链路层面）。
  - 未对目标库执行 `db migrate`（沿用既有惯例：线上 additive 变更随部署由容器 `db init`/`db migrate` 应用）。
- 数据层（`database.service.ts`）：`UserRecord`/`UserSessionRecord`；`createUser`/`findUserByUsername`/`findUserById`/`listUsers`/`findFirstAdminUser`/`disableUser`；`createUserSession`/`findUserSessionByTokenHash`/`deleteUserSessionByTokenHash`/`deleteUserSessionsByUserId`/`purgeExpiredUserSessions`；`backfillConversationUserId`（仅填 NULL，幂等）；`createConversation(title,userId?)`、`listConversations(userId?)`、`getConversation(id,userId?)`（非本人视为不存在，抗 id 枚举）。
- 启动哨兵：`EXPECTED_TABLES` 增 `worker_job`/`worker_heartbeat`/`user`/`user_session`；新增 `conversation.user_id` 列存在性快检（存量库未迁移时快速失败）。
- 引导（`src/user-auth/`）：`password.util.ts`（scrypt 随机 salt，`scrypt$salt$hash`，`timingSafeEqual` 比较，非法格式返回 false 不抛错）；`UserSeedService`（启动幂等播种 admin；`ADMIN_INITIAL_PASSWORD` 缺失仅告警、**不建默认密码**；已存在 admin 不动；随后把 `conversation.user_id` 为空的存量行回填归首个 admin，无 admin 则 no-op）；`UserAuthModule` 接入 AppModule。
- 目录命名：新代码在 `src/user-auth/`（`src/auth/` 已被 B站扫码登录占用）；HTTP 路径仍为 `api/auth/*`。

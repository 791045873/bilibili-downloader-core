## Stage 2 — auth 核心（登录 / 登出 / me + 会话 + 登录锁定）

- `auth.constants.ts`：`SESSION_COOKIE_NAME='bdl_session'`、`ROLE_ADMIN/ROLE_USER`、`AuthUser`（仅 id/username/role，不含凭据）。
- `cookie.util.ts`：手动解析 `Cookie` 请求头（项目未装 cookie-parser，避免新增依赖）；URL 解码失败回退原值、非法条目跳过、重复名取首个。
- `auth.service.ts`：
  - token = `randomBytes(32).base64url`，**仅 sha256 摘要入库**；Cookie 传原 token。
  - `login`：先判 IP 封禁 → 取用户 → 口令校验（**用户不存在时对哑哈希做等价开销校验**，抹平用户名枚举时序）→ 失败计数/清零 → 清理过期会话 → 建会话。密码错误 / 用户不存在 / 已禁用统一返回 `invalid`。
  - 登录失败锁定：内存 `Map<ip, {count, firstAt, blockedUntil}>`，阈值/窗口/封禁时长经 env（默认 5 次 / 15 分钟窗口 / 封禁 15 分钟）。
  - `resolveUser`：无 token / 会话不存在 / 过期（顺带清理）/ 用户不存在 / 已禁用 → 未登录。
  - `cookieOptions`：HttpOnly + SameSite=Lax + 生产 Secure + path=/ + maxAge（`SESSION_TTL_HOURS` 默认 168h）。
- `user-auth.controller.ts`（`api/auth`，与 B站扫码控制器全路径不冲突）：`POST login`（成功置 cookie；封禁返回 429 + `Retry-After`；失败 401 通用文案）、`POST logout`（吊销 + `clearCookie`）、`GET me`（401 或当前用户）。
- `UserAuthModule` 注册控制器与 `AuthService`。

## Stage 3 — 守卫与权限落位（后端门禁）

- `auth.decorators.ts`：`@Public()`、`@Roles(...)`、`@CurrentUser()`（从 `request.user` 取当前用户）。
- `auth.guard.ts` `AuthGuard` 注册为 `APP_GUARD`（全局，fail-closed）：
  - `@Public()` 放行；否则解析 `bdl_session` → `AuthService.resolveUser`，无效 401；
  - **角色缺省即 admin**：未标注 `@Roles` 的路由仅 admin 可用，不匹配 403。这比计划文字（"默认需登录"）更严，效果与逐条映射一致，且新增端点漏配时默认关闭。
- 显式放开：
  - `@Public()`：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。
  - `@Roles(admin,user)`：`api/chat/*`（类级）、`GET /api/summary-tasks/by-resource/:bvid/:cid/markdown`（方法级；同类 `/:id/markdown`、`/:id/raw-response` 仍 admin）。
  - 其余（download / analysis / analysis-task / prompt / worker-jobs / video / parse / knowledge / B站扫码登录）按默认即 admin-only，无需逐个改动。
- QA 会话隔离：`chat.controller` 全部方法取 `@CurrentUser()`，`createConversation(undefined, user.id)`、`listConversations(user.id)`、`requireConversation(id, user.id)`；**admin 亦仅见自己的会话**（存量已回填归 admin）；他人/不存在/已删除统一 **404**（抗 id 枚举）。

## Stage 4 — admin 用户管理接口

- `users.controller.ts`（`api/users`；未标 `@Roles` → 全局守卫默认仅 admin）：
  - `POST /api/users`：用户名 3-32 位 `[A-Za-z0-9._-]`、密码 8-200 位、角色仅 `admin`/`user`（缺省 user）；重复用户名 **409**；入库仅存 scrypt 摘要。
  - `GET /api/users`：返回 `{id, username, role, createdAt, disabledAt}`，**恒不含 password_hash**。
  - `POST /api/users/:id/disable`：写 `disabled_at` + 吊销该用户全部会话，返回 `sessionsRevoked`；**幂等**。
- 防锁死加固（超出计划的安全加固）：拒绝禁用**自己**、拒绝禁用**最后一个可用 admin**（均 403）。

## Stage 5 — 前端登录与会话态

- 命名隔离：新用户系统落 `/sign-in` + `pages/SignIn.tsx` + `stores/session.ts`（`/login` + `stores/auth.ts` 已被 B站扫码登录占用），两套会话态互不干扰。
- `api/index.ts`：`request()` 统一 `credentials: "include"`；遇 **401** 广播 `bdl:unauthorized`（`appMe` boot 探测经 `silentUnauthorized` 抑制，避免首屏误报）；新增 `appLogin` / `appLogout` / `appMe` / `listAppUsers` / `createAppUser` / `disableAppUser`。
- `stores/session.ts`：`{user, status: unknown|authenticated|anonymous, fetchMe, login, logout, markAnonymous}` + `isAdmin(user)`；模块级监听 `bdl:unauthorized` → `markAnonymous()`，401 拦截只在一处实现。
- `App.tsx` 门禁（渲染前早退）：
  - `unknown` → `<Spin/>`（避免未定会话态时闪现受限内容）；
  - `anonymous` → `/sign-in` 裸渲染，其余路径 `<Navigate to="/sign-in" state={{from}}/>`；
  - 已登录访问 `/sign-in` → 按角色回 `/`（admin）或 `/qa`（user）；
  - **非 admin 的路径级门禁**：仅 `/qa` 与 `/summary/:bvid/:cid` 放行，其余重定向 `/qa`——直接输入 URL 同样拦得住，不只隐藏导航。
  - `NAV_ITEMS` 加 `adminOnly` 过滤；B站账号区块与 `checkLogin()` 仅 admin 触发；新增用户名 + 「退出」。
- `pages/AppUsers.tsx`（`/users`，admin-only，**超出计划的补齐**）：列表（用户名/角色/状态/创建时间）、新建（前端校验与后端一致：3-32 位 `[A-Za-z0-9._-]`、密码 8-200、角色 user/admin）、禁用（二次确认，禁用自己按钮置灰）。理由：需求将“用户管理”列为 admin 能力，无 UI 则普通用户只能靠 curl 创建。

## 实施

- **数据层**：contract 新增 `Conversation`/`Message` → `prisma contract emit` → 迁移 `migrations/app/20260909T1031_chat_conversations`（from 248ea，4 条 additive）。首次生成时 refs/db.json（gitignored 本地追踪）停留在 5f0ca 导致迁移混入 integrity 列重放——`prisma migration ref set db 248ea…` 修正后重生成，最终迁移仅含 chat 两表。RDS 上 integrity 列已由上次部署的容器 `db init` 自动演进（实测确认），与迁移链终态一致；部署新镜像时 `db init` 将自动应用 chat 两表，无需手动迁移。
- **启动哨兵**：`EXPECTED_TABLES` 加 `conversation`/`message`；本地实测缺表时启动失败并给出明确指引（符合设计）。
- **照片链路**：server 新增 `sharp` + `multer`（首个 multipart 先例，`AnyFilesInterceptor`）；`CosStoreService` 新增 `uploadBuffer`；`ChatPhotoService` 校验（jpeg/png/webp、大小上限）→ 压缩（最长边/质量/EXIF 方向）→ COS `user-photos/<conversationId>/<uuid>.jpg`。
- **问答编排**（`packages/server/src/chat/`）：`ChatController`（会话 CRUD、照片、消息端点）、`ChatService`（配置预检→落 user message→query 重写→照片分析→检索（score=1-`<=>` 余弦相似度，≥ `CHAT_HIT_THRESHOLD` 判命中）→生成（JSON 信封 + `response_format:json_object`，视觉输入默认开）→引用解析→三段式→持久化）、`chat-prompt.ts`、`citation.ts`（`[n]` 解析纯函数）。兜底：命中为空 → 服务端固定文案"知识库暂无相关内容"，不调用生成。装配：`EmbeddingService` 加入 `AnalysisModule` exports；QwenClient 沿用"读配置后自行构造"先例。
- **前端**：`/qa` 路由（lazy，`export function Component()` 约定——首版用 default export 触发 react-router 类型不匹配，已修正）+ 顶部导航"穿搭问答"；`QaChat.tsx` 会话列表/删除（Popconfirm）/新建、消息流、照片多选上传（≤3）、三段式渲染（ReactMarkdown 正文 + antd Image 失效降级 + `?t=` 跳转注脚）；api/types 手写扩展。
- **env**：`CHAT_VISUAL_INPUT/CHAT_HIT_THRESHOLD/CHAT_HISTORY_ROUNDS/CHAT_RETRIEVAL_K/PHOTO_MAX_EDGE/PHOTO_JPEG_QUALITY/PHOTO_MAX_UPLOAD_MB/PHOTO_MAX_PER_MESSAGE` 登记 `.env.example` 与 compose（均有默认值）。

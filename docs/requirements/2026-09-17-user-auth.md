# 需求：小用户系统与写操作鉴权（auth）

> 来源：拆自 `docs/discussions/2026-09-17-cloud-nas-responsibility-split.md`（Q11）
> Owner Doc：`docs/design/app-overview.md`（用户角色）、`docs/architecture/system-baseline.md`
> 前置：Phase 3（cloud-server / nas-worker 拆分）建议先落地；本需求作用于 `cloud-server`
> 保护区：**auth（`plan-first`）**——需 owner doc + 测试；reviewer availability=none 时实现 blocked，需人工 / 子代理评审
> 状态：实现就绪（1 项实现细节见 Open Questions）

## Goal

为对外访问引入**小用户系统**：内置 `admin` 用户拥有全部写权限；普通 `user` 仅能使用 QA 问答。QA 会话按用户隔离。NAS↔云的服务身份用最小权限 DB 角色，不引入服务令牌。

## In Scope

### 用户与会话（Prisma contract + migration，additive）

- 新增 `user` 表：`id`、`username`（唯一）、`password_hash`、`role`（`admin` / `user`）、`created_at`、`updated_at`、`disabled_at`（可空）。
- 新增 `user_session` 表（服务端 session，可吊销）：`id`、`token_hash`、`user_id`、`created_at`、`expires_at`。
- `conversation` 新增 `user_id` 外键（可空，后续按需收紧）；**存量会话统一归 admin**（幂等回填）。
- 迁移与回滚遵循讨论 `Migration & Rollback`。

### 鉴权与登录

- 登录 / 登出 / 当前用户接口；会话经 **HttpOnly Cookie**（与 B站 扫码 cookie 命名 / 路径隔离）。
- **admin 引导**：首次启动由 `ADMIN_INITIAL_PASSWORD` 播种 admin；不存在则创建、存在则不动；**环境变量缺失时启动告警且不创建默认密码**。
- **普通用户来源**：由 admin 创建 / 邀请，**不开放自助注册**。
- 密码哈希：见 Open Questions（推荐 Node 内置 `crypto.scrypt`，不新增依赖）。

### 权限矩阵

- `admin`：全部（下载 / 分析触发、删除、重建 / 重试截图、完整性检查、设置 / 提示词、任务 / 总结管理、用户管理）。
- `user`：QA（自己会话的 CRUD、照片上传、发消息）+ 按 `(bvid,cid)` 读"AI 总结"整页。
- 其余读接口（下载列表、总结任务列表、设置等）仅 admin。
- 未登录 / 越权返回 401 / 403。

### 服务身份（NAS↔云）

- NAS worker 直连云 DB 用**独立最小权限 DB 角色**、直连 COS 用专用密钥；无需服务令牌。

## Out Of Scope

- 公开注册 / 第三方 OAuth / 支付。
- 限流（本期不做）。
- 角色扩展（仅 admin / user 两级）。
- 反向隧道 / 服务令牌（当前无 NAS↔云 HTTP 通道）。

## Main User Flows

### admin 登录与写操作

1. admin 用初始密码登录 → 建立会话。
2. 执行下载 / 分析 / 删除 / 设置等写操作。

### 普通用户 QA

1. 普通用户登录（由 admin 创建）→ 进入 QA。
2. 新建 / 查看 / 删除**自己的**会话、上传照片、发送消息；可打开来源"AI 总结"整页。
3. 访问管理类接口 → 403。

## Business Rules

- **仅 admin 可写**；普通用户仅 QA。
- **会话隔离**：用户只能访问自己的 `conversation`。
- **存量会话归 admin**。
- **无默认密码**：未配置 `ADMIN_INITIAL_PASSWORD` 时不创建 admin 凭据，仅告警。
- **会话可吊销**：登出 / 禁用用户使会话失效。

## Roles / Permissions

- 见上"权限矩阵"。单用户工具自此升级为两级角色。

## Data / Model Impact

- 新增 `user`、`user_session`；`conversation.user_id`（additive + 回填归 admin）。
- 属 auth 保护区，需 owner doc + 测试。

## API / Integration Impact

- 新增 `/api/auth/login`、`/api/auth/logout`、`/api/auth/me`，以及 admin 的用户管理接口（创建 / 列表 / 禁用）。
- 既有管理类接口加鉴权与角色校验；QA 接口按 `user_id` 过滤会话。
- 前端增加登录页与会话态（管理页仅 admin 可见）。

## Edge Cases

- `ADMIN_INITIAL_PASSWORD` 缺失：启动告警，不创建默认密码。
- 会话过期 / 被吊销：返回 401，前端跳登录。
- 用户被禁用：其会话失效，QA 不可用。
- 存量会话无归属：迁移回填归 admin。
- 普通用户访问他人会话：404 / 403。
- 并发登录：允许多会话（`user_session` 多行），或按计划限制。

## Open Questions

- **密码哈希算法**：推荐 Node 内置 `crypto.scrypt`（无新依赖）；备选 `argon2` / `bcrypt`。实现时定，不影响契约。

## Acceptance Criteria

- [ ] `user` / `user_session` / `conversation.user_id` 经 contract/emit/migration 落地；存量会话回填归 admin。
- [ ] admin 由 `ADMIN_INITIAL_PASSWORD` 首次播种；缺失时告警且不建默认密码。
- [ ] 登录 / 登出 / me 可用；会话经 HttpOnly Cookie，与 B站 cookie 隔离。
- [ ] 写操作仅 admin；普通用户仅 QA 且只能访问自己的会话；越权返回 403 / 401。
- [ ] 按 `(bvid,cid)` 读"AI 总结"整页对普通用户开放。
- [ ] 登出 / 禁用使用户会话失效。
- [ ] `pnpm typecheck`、`pnpm build` 通过；鉴权与权限数据层测试通过；owner doc 更新。
- [ ] auth 保护区经人工 / 子代理评审（reviewer=none 时不得 cold-replay 代替）。

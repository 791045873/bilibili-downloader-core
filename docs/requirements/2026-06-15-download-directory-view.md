## Problem

当前 Web 入队流程已有“确认下载目录”弹框，但该字段实际表示 `OUTPUT_DIR` 下的相对子目录；用户无法在 Web 中查看当前服务端下载根目录，也无法在下载列表中直接看到完成文件的实际输出位置。

这会造成两个问题：

- 用户以为弹框中填写的是完整磁盘目录，但后端实际会拼到服务端 `OUTPUT_DIR` 下。
- 下载完成后，用户需要到服务端或容器环境中猜测文件实际落盘位置。

## In Scope

- 在后端提供只读 API，用于返回当前下载根目录信息。
- 在前端设置页展示当前下载根目录，说明它来自服务端环境配置，并提供复制能力。
- 在下载列表中展示任务的实际输出文件路径（当后端已返回 `outputFile` 时）。
- 调整相关文档，明确“入队弹框填写的是下载根目录下的相对子目录”。
- 保留现有 `outputPath` 入队行为：用户仍可在入队时指定相对子目录。

## Out Of Scope

- 不在 Web UI 中修改服务端 `OUTPUT_DIR` 环境变量。
- 不新增跨平台目录选择器或打开本机文件夹能力。
- 不改变 Docker volume 挂载规则。
- 不迁移历史任务数据库结构。
- 不改变 CLI 的输出目录参数行为。

## Business Rules

- 服务端下载根目录来源保持现状：优先使用 `process.env.OUTPUT_DIR`，否则使用 server 进程工作目录下的 `downloads`。
- 前端展示的根目录是服务端视角路径，不保证等同于浏览器所在机器路径。
- 入队弹框中的 `outputPath` 必须继续作为相对子目录处理，不允许通过 Web 请求覆盖服务端下载根目录。
- 下载列表只在有实际 `outputFile` 时展示文件路径；排队或下载中任务可以不显示完整文件路径。

## User Flows

### 查看当前下载根目录

1. 用户打开设置页。
2. 页面请求服务端目录信息。
3. 页面展示当前下载根目录与配置来源。
4. 用户可以复制该路径。

### 入队时指定相对子目录

1. 用户在视频详情页点击加入下载队列。
2. 弹框展示默认相对子目录。
3. 用户可确认或修改该相对子目录。
4. 服务端将最终文件输出到 `下载根目录 / 相对子目录 / 文件名.mp4`。

### 查看完成文件位置

1. 用户打开下载列表。
2. 任务完成后，任务卡片显示实际输出文件路径。
3. 用户可以查看该路径文本。

## API Contract

### `GET /api/download/config`

Response:

```json
{
  "outputDir": "C:\\path\\to\\downloads",
  "source": "env" | "default"
}
```

- `outputDir`: 服务端当前下载根目录的绝对路径。若 `OUTPUT_DIR` 配置为相对路径，服务端返回按当前工作目录解析后的绝对路径。
- `source`: `env` 表示来自 `OUTPUT_DIR`，`default` 表示使用默认目录。

# 下载入队创建层去重（bvid+cid）

## 背景

用户要求：入队时若同视频（BVID 对比）确定已下载过且磁盘对应位置确有文件，则不再创建新的下载任务。经确认口径：

- 匹配键：**bvid + cid**（多P视频各分P独立判定，与文件产出口径一致；用户选项）。
- 拦截范围：① 同资源存在 `created`/`downloading`（排队中/下载中）任务；② 同资源存在 `success` 任务且其 `outputFile`（经 `join(DOWNLOAD_ROOT, value)` 解析）在磁盘真实存在。两类都拦截。
- 此决策**有意推翻** 2026-08-10 的"创建层不去重、以执行时磁盘存在性为唯一裁决"决策（`docs/plans/2026-08-10-download-enqueue-dedup-ux-plan.md` Deferred 节）；前端"已下载"展示标记保留（展示性，不拦截，用户仍可勾选，由服务端拒绝并提示）。

## 需求

1. `POST /api/download`（经 `DownloadService.createTask`）创建任务前按 (bvid, cid) 判定：
   - 存在进行中/排队中任务 → 拒绝创建，提示"该视频已有排队中/下载中的任务，未重复创建"。
   - 存在 success 任务且磁盘文件存在 → 拒绝创建，提示"该视频已下载且文件存在，未重复创建"。
2. 拒绝时 HTTP 409 + 中文消息；前端入队处把该提示作为**非错误**信息呈现给用户（不标红为"失败"语义，可接受现有 error 展示但消息文本必须可见）。
3. 内部调用方豁免：`analysis-video-resolver` 截图回退的同步 `createTask + executeTask` 链路不走去重（`skipDedup`），保持现有行为。
4. 文件被手动删除后（success 记录在但磁盘无文件）不拦截，正常创建新任务。

## 验收标准

- AC1 已下载且文件在盘的资源重复入队 → 409 + 对应提示，DB 无新任务行。
- AC2 同资源排队中/下载中时重复入队 → 409 + 对应提示，DB 无新任务行。
- AC3 文件被删后的重复入队 → 正常创建任务。
- AC4 不同分P（不同 cid）互不影响。
- AC5 resolver 截图回退链路行为不变。
- AC6 前端两个入队页（VideoDetail、ParseResultList）能看到拒绝提示文本。
- AC7 `pnpm typecheck`、`pnpm build`、server 测试全绿。

## 边界与假设记录

- 竞态：判定与插入非原子，两个并发同资源请求理论上可能双建（无唯一索引）——接受为残余风险，与现有调度模型一致。
- 画质不计入判定：success+文件存在即拦截（默认模板文件名含画质段，不同画质本就不同文件；自定义模板无画质段时以"文件存在"为准）。
- 去重判定基于 DB 最新记录 + 磁盘校验，不做全表扫描。

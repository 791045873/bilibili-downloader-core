# 2026-08-11 AI 总结视频资源可用性对账 — 测试方向

关联计划：`docs/plans/2026-08-11-ai-summary-resource-availability-plan.md`

本文件描述资源可用性对账应观察到的需求级状态与反状态，供计划验证与闭核算使用。验证命令：`pnpm typecheck`（零错误）+ 下述手工回归。

## 1. 低清视频复用前磁盘校验

**应成立:**

- 重新触发 AI 总结时，若 DB 中子任务 `status=completed` 且 `outputFile` 对应文件在磁盘上不存在，系统不会直接复用该路径。
- 低清文件缺失时，系统会重新调度低清下载，任务保持在"等待/进行中"而非直接失败或复用失效路径。

**不应成立:**

- 引用磁盘上已删除的低清文件路径进行分析。
- 低清缺失时静默复用或静默生成空文档。

## 2. 高清视频缺失时截图源降级链恢复

**应成立:**

- 高清 `outputFile` 被删除后触发分析，LLM 分析视频可回退到低清（存在时）或触发低清重下。
- `screenshotVideoPath` 失效时不透传给引擎，截图源走 `ScreenshotSourceResolver` 降级链（远端流 → DB 已完成下载 → 同步重下），截图为空不再是默认结果。

**不应成立:**

- 高清缺失却仍直接以失效路径作为截图源，导致所有段落截图为空且无降级。

## 3. 截图源"已完成本地下载"回退前磁盘校验

**应成立:**

- `findCompletedTaskByBvidAndCid` 命中的本地文件在磁盘上存在时才可作为截图源。
- 该文件缺失时回退不可用，继续走同步重下或报明确错误。

**不应成立:**

- 引用 DB 中已删除的旧下载文件作为截图源。

## 4. 任务重载 outputFile 磁盘校验

**应成立:**

- `resolveTaskForAnalysis` 重载其它 completed 任务的 `outputFile` 前校验磁盘；失效时不采用该路径。
- 无可用资源时给出明确错误信息（任务落 `failed`），而非复用失效路径。

**不应成立:**

- 重载后使用磁盘上不存在的文件继续分析。

## 5. 手动删除文件后重触发可自动恢复

**应成立:**

- 用户手动删除低清文件后，再次点击"重新 AI 总结"，链路自动重下低清并完成分析（无需重启或手动清理 DB）。

**不应成立:**

- 重触发后永久卡住、报错且无恢复手段。

## 6. 既有行为不回归

**应成立:**

- 文件存在时仍按原有复用逻辑（低清优先/高清复用）执行，不额外触发无谓下载。
- `文件已存在, 跳过下载`（core 跳检）语义不变。

**不应成立:**

- 磁盘校验引入额外下载、重复下载或改变"已存在即跳过"行为。

## 手工回归清单

- 场景 A：正常下载完成后自动总结成功（基线）。
- 场景 B：删除低清文件 → 重新触发 → 自动重下并成功。
- 场景 C：删除高清文件 → 重新触发 → LLM 用低清、截图走降级链。
- 场景 D：删除高清+低清 → 重新触发 → 重下低清并完成，无空截图。
- 场景 E：`pnpm typecheck` 零错误。

运行级场景（B/C/D）需要运行中的 server、真实 B 站视频与有效的 QWEN/Python 代理配置，无法在静态验证中复现；逻辑级已通过代码检查覆盖（磁盘校验点、缺失重下分支），运行级行为留用户手动验证。`pnpm typecheck`、`pnpm build` 已在实施时通过。

范围外（由其他计划覆盖）：状态卡死/重启对账（触发健壮性计划）、资产层与状态收敛（架构收敛计划）。

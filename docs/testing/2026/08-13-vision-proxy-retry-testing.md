# 2026-08-13 Vision Proxy 代理路径自动重试 — 测试方向

关联计划：`docs/plans/2026-08-13-vision-proxy-retry-plan.md`

本文件描述 `multimodalChat` 代理路径重试行为应观察到的需求级状态与反状态，供计划验证与闭核算使用。验证命令：`pnpm typecheck`、`pnpm build` + 下述运行级 stub 冒烟。

## 1. 瞬时 5xx 重试后恢复

**应成立:**

- 代理首次返回 500/502/503（模拟 DashScope 连接重置），第二次返回 200 时，`multimodalChat` 自动重试并成功返回，最终结果与一次性成功一致。
- 成功路径总调用次数 = 2（首试失败 + 1 次重试）。

**不应成立:**

- 首次 5xx 直接抛错导致整单失败（无重试）；重试超过 1 次。

## 2. 持续 5xx 最终报错

**应成立:**

- 代理持续返回 500 时，`multimodalChat` 重试 1 次后抛出与现状一致的错误信息（含 `status=500` 与端点），总调用次数 = 2。

**不应成立:**

- 无限重试；错误信息丢失状态码/端点；只调用 1 次就抛（未尝试重试）。

## 3. 网络层错误重试

**应成立:**

- 首次 fetch 因网络错误（如连接被重置/拒绝，非超时）失败，第二次成功时，`multimodalChat` 重试后成功。

**不应成立:**

- 网络瞬时错误直接抛错（无重试）。

## 4. 超时不重试

**应成立:**

- 代理长时间不响应触发超时（AbortError）时，`multimodalChat` 立即抛超时错误，**不额外等待重试**。

**不应成立:**

- 超时后再次发起调用（叠加负载、延长等待）。

## 5. 4xx 不重试

**应成立:**

- 代理返回 400/413/404 等确定性客户端错误时，`multimodalChat` 立即抛错，不重试，总调用次数 = 1。

**不应成立:**

- 对客户端错误进行无意义重试。

## 6. 正常成功路径不回归

**应成立:**

- 代理首次即返回 200 时，总调用次数 = 1（无多余重试），返回体/解析结果与之前一致。
- 最终失败（重试后仍失败）的错误信息格式与改造前一致。
- `pnpm typecheck`、`pnpm build` 零错误。

**不应成立:**

- 成功路径出现额外重试；正常调用被误判为重试对象。

## 运行级观测方式

- 用 Node 脚本 + 本地 stub HTTP server 按状态序列模拟代理行为，直接调用构建产物中的 `QwenClient`：
  - stub 返回序列 `[500, 200]` → 方向 1（最终成功，调用计数 2）。
  - stub 恒定 `500` → 方向 2（最终报错，调用计数 2）。
  - stub 端口监听后立即断开首个连接（ECONNRESET）第二次正常 → 方向 3。
  - stub 收到请求后不响应 → 方向 4（`visionProxyTimeoutMs` 设小值，如 800ms，断言超时抛错且仅 1 次调用）。
  - stub 恒定 `413` → 方向 5（调用计数 1，立即失败）。
  - stub 恒定 `200` → 方向 6（调用计数 1）。
  - 每次断言后打印调用计数与最终错误/结果。
- 逻辑级：代码检查覆盖重试条件（仅网络错误与 500/502/503）、AbortError 与 4xx 分支直接抛出。

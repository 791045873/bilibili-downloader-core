# 2026-08-21 LLM 时间戳解析兼容 测试验证

关联计划：`docs/plans/2026-08-21-timestamp-parse-compat-plan.md`

## 验证范围

本测试文档描述截图时间戳解析兼容改动后应保持的可观察状态。本次变更只影响"按 LLM 返回时间戳截图"这一步的解析与择优：合法 `hh:mm:ss` / `mm:ss` 截图行为不得回归；模型返回的三段式若实为"分:秒:毫秒"，应能按前两段重算并截到正确画面；解析与择优的过程应在日志中可观察。

## 前提

- 本机可运行 `pnpm`；Node ≥22 支持 `node --experimental-strip-types`（本机 v22.22.3 满足）。
- server 无单元测试设施（仓库基线），采用既有真实代码断言方式（临时脚本，不入库）。
- 真实 ffmpeg 截图端到端依赖 B 站流/本地视频与 LLM 密钥，不在本仓执行；以纯函数断言 + 编译验证覆盖解析择优逻辑，真实视频截图验证留人工运行级（见"范围外裁定"）。

## 测试方向

### 解析兼容（`parseTimestampCandidates`）

- [x] 应成立：三段合法 `hh:mm:ss` 产出文档化候选（`00:02:30` → 150），同时产出前两段"分:秒"候选（`00:02` → 2），两者去重保序。
- [x] 应成立：两段 `mm:ss` 正常（`02:30` → 150）；分钟 ≥60 的两段（`70:30` → 4230）不再被拒。
- [x] 应成立：三段第三段 ≥60（`02:30:500`，实为分:秒:毫秒）→ 默认候选无效，仍产出前两段候选 150。
- [x] 应成立：三段第三段 <60（`05:32:40`，实为分:秒:毫秒）→ 同时产出文档化候选 19960 与前两段候选 332。
- [x] 不应成立：空串、纯字母、非纯数字段、仅一段、四段及以上产出任何候选（应 `[]`）。
- [x] 不应成立：三段中第二段 ≥60（`01:60:00`）或两段秒 ≥60（`12:60`）产出候选。

### 时长择优（`pickTimestampSeconds`）

- [x] 应成立：时长未知时取首候选（与现状默认解读一致）。
- [x] 应成立：时长已知时取第一个 ≤ 时长的候选：`[19960, 332]` 配 350s 取 332；`[150, 2]` 配 600s 取 150。
- [x] 不应成立：全部候选超出时长时返回有效秒数（应 `undefined`，该段跳过）。
- [x] 不应成立：`duration` 为 `NaN`/负值/`Infinity` 等非有限非负值时触发择优筛选（应视为未知，返回首候选，与现状默认解读一致）。

### 引擎行为（截图选择）

- [x] 应成立：截图循环前对截图源探测一次时长（失败时 warn 并退化为默认解读，不影响现有截图）。
- [x] 应成立：每段时间戳解析后，日志在跳过场景中包含原始时间戳、候选与时长上下文。
- [x] 不应成立：本次变更影响 API 契约、文档生成、`raw_response` 存储或部署配置。

### 内置提示词

- [x] 应成立：`AI_PROMPT_FORMAT_SNIPPET` 与内置提示词示例为"格式为 `hh:mm:ss` 或 `mm:ss`，分钟和秒需小于 60"，示例 `00:02:30代表2分30秒`；`2分20秒` 旧示例在活动代码中无残留。
- [x] 不应成立：本次变更迁移或改写任何已保存的自定义提示词。

### 编译与运行稳定

- [x] 应成立：`pnpm typecheck`、`pnpm build` 全部通过。
- [x] 不应成立：`transTimestampToSeconds` 在活动代码/文档中有残留引用（历史留档除外）。

### 范围外裁定

- [x] 已裁定：真实 B 站视频 + LLM 端到端截图验证——需用户密钥/外部网络/完整分析环境，不执行；纯函数断言与编译验证覆盖解析择优逻辑，运行级人工验证为残余项。
- [x] 已裁定：历史留档（plan/log/audit/requirements/testing 旧记录）中出现的 `transTimestampToSeconds` 与 `2分20秒` 表述——历史留档不修改、不参与残留扫描。

## 结果

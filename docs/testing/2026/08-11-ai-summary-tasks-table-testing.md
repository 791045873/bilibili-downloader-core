# 2026-08-11 AI 总结任务列表表格化 — 测试方向

关联计划：`docs/plans/2026-08-11-ai-summary-tasks-table-plan.md`

本文件描述表格化列表应观察到的需求级状态与反状态，供计划验证与闭核算使用。验证命令：`pnpm typecheck`（零错误）+ `pnpm build`（零错误）+ DB 冒烟 + 下述手工回归。

> 2026-08-11 修正：本列表的「重要的时间节点」指 AI 总结任务的**执行耗时**（LLM 分析耗时、截图耗时、总计），非视频内容时间戳。视频内容时间戳（key_timestamps）代码已回退。

## 1. 表格化展示

**应成立:**

- AI 总结任务页以表格形式展示所有任务，每行一个资源级总结任务。
- 表格列包含：视频标题、状态、总结时间、执行耗时、总结输出/错误信息、更新时间。

**不应成立:**

- 仍为卡片式列表布局。

## 2. 总结时间列

**应成立:**

- 已完成的总结（completed/failed）显示 `lastCompletedAt`（本地时间格式）。
- 未完成（pending/analyzing）的总结时间显示占位（如 `—`），不显示误导时间。

**不应成立:**

- 未完成任务显示旧的 completedAt 或乱码时间。

## 3. 执行耗时列

**应成立:**

- 总结完成的任务显示执行耗时明细：LLM 分析时长、截图时长、总计时长（如 `LLM 12.0s · 截图 5.0s · 总计 18.0s`；<1s 显示 ms）。
- 空内容总结或历史任务（未持久化）显示 `—`。
- 数据来自 `ai_summary_task.execution_timing`（JSON），列表接口返回对象。
- **重跑语义**：重新触发（pending/analyzing）或失败后，旧执行耗时被清空，该列显示 `—`；成功后才重新写入。

**不应成立:**

- 显示原始 JSON 字符串、视频内容时间戳（回退项）或把截图时刻误当耗时。
- 重跑失败/进行中时仍展示上一次成功的执行耗时。

## 4. 状态与错误展示

**应成立:**

- 状态标签（待总结/总结中/总结失败/总结完成）在表格中清晰可辨。
- 失败任务显示错误信息；成功任务显示总结输出（md 路径，过长截断）。

**不应成立:**

- 状态与错误信息丢失或溢出破坏表格布局。

## 5. 服务端持久化（Phase 1）

**应成立:**

- `ai_summary_task` 存在 `execution_timing` 列（幂等迁移，可空）。
- 总结成功后 `execution_timing` 写入本次 LLM/截图/总计耗时（JSON）；失败/分析中不写或为空。
- `GET /api/summary-tasks` 返回解析后的 `executionTiming` 对象（坏 JSON/缺字段回退 `undefined`，不报错）。

**不应成立:**

- 迁移重复执行报错；耗时测量缺失或与实际不符；接口返回原始字符串或 500。

## 6. 既有行为不回归

**应成立:**

- 任务状态流转、刷新按钮、空态/错误提示行为不变。
- 其它消费 `ai_summary_task` 的接口（如 `GET /api/tasks` 的 summaryStatus）不受新列影响。
- 仓库中无 `keyTimestamps`/`key_timestamps`/`keyNodes` 残留引用（回退彻底）。

**不应成立:**

- 新列或前端改动破坏既有列表接口或其它页面；回退残留视频时间戳代码。

## 手工回归清单

- 场景 A：有 completed 任务的列表 → 表格渲染、总结时间正确、执行耗时显示 LLM/截图/总计（真实 B 站视频）。
- 场景 B：pending/analyzing 任务 → 总结时间与执行耗时均显示 `—`。
- 场景 C：failed 任务 → 状态与错误信息正确，执行耗时 `—`。
- 场景 D：历史任务（无 execution_timing）→ 执行耗时列显示 `—`，接口不报错。
- 场景 E：`pnpm typecheck` 与 `pnpm build` 零错误；grep 无 key_timestamps 残留。

运行级场景（A）需要运行中的 server 与真实 B 站视频 + QWEN/Python 代理；逻辑级已通过代码检查 + DB 冒烟覆盖。运行级行为留用户手动验证。

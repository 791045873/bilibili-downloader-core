# 09-09 RAG 问答服务与前端 Testing

> 需求：`docs/requirements/2026-09-09-rag-chat-service.md`
> 计划：`docs/plans/2026-09-09-rag-chat-plan.md`
> 定位：记录需求级观察态（用户/系统应呈现什么、不应呈现什么），非测试脚本。

## 检查应覆盖的状态

### T1 会话生命周期

- 新建会话成功，出现在列表顶部（按最近更新倒序）。
- 新建第二个会话后，第一个会话仍完整保留，消息不丢失。
- 点击任意旧会话可回看全部历史消息（含三段式回答内容）。
- 在旧会话继续发送消息，回答上下文与中断前连续（省略式追问能衔接旧话题）。
- 删除会话经二次确认后从列表消失，其消息不可再访问（API 层 404）。
- server 重启后所有会话与消息仍完整可回看。

### T2 场景二（文本问答）

- 输入与知识库字面不同但语义相同的问题（如"小个子怎么穿显高"），回答内容对应表述不同的技巧（如"高腰线显腿长"），证明走向量检索而非关键词。
- 回答正文含 `[n]` 引用标记；正文下方展示被引技巧的截图（images 区）；页面底部展示视频注脚（标题 + 链接 + `?t=` 时刻），不与正文图片混排。
- 被引标记与 images/sources 一一对应，无越界或悬空引用。

### T3 场景一（照片问答）

- 上传穿搭照片发送后，照片先压缩再出现在 COS 专属目录（`user-photos/` 前缀）下，且消息中展示的是压缩后的 COS URL。
- 回答内容针对照片中的穿搭给出建议，而非泛泛回答。
- 不支持的照片格式 / 超大小上限 → 明确报错，消息不发送。

### T4 兜底

- 提问完全超出知识库范围（或知识库为空）时，回答为固定兜底文案"知识库暂无相关内容"，无 images/sources。
- 兜底回答中不出现编造的穿搭方法或通用常识。

### T5 多轮与 query 重写

- 先问"小个子怎么穿显高"，再追问"那配什么鞋子"，第二轮回答检索的是"小个子 配什么鞋子"语境，而非孤立关键词。
- 历史超过窗口轮数后，最早的轮次不再影响生成，但界面仍完整显示全部历史。

### T6 配置开关与降级

- `CHAT_VISUAL_INPUT=false` 时回答仍正常生成（纯文本），截图仅在前端展示区出现。
- 缺 LLM 配置（未设置 llm.apiKey/modelName）时发送消息得到明确 503 语义错误，而非静默失败或 500 堆栈。
- 缺 embedding/COS 配置时对应环节错误语义明确、可重试。

### T7 模型来源

- 照片分析与聊天生成调用的是设置页当前配置的模型（可通过日志/请求记录确认模型名 = `llm.modelName`），无需任何新模型配置项。

### T8 照片不入知识库

- 上传照片并发起问答后，`summary`/`summary_segment` 表与 `/api/knowledge/search` 结果中均不出现用户照片 URL。

## 不应发生

- 不应出现编造知识库外方法的回答（违反严格兜底）。
- 用户照片不应进入 `summary/` COS 前缀或知识库表。
- 删除会话不应残留可访问的消息记录（DB 级联）。
- 新建/删除会话不应影响其他会话的数据。
- 问答 API 不应引入鉴权或改变现有 `/api/*` 的访问语义。

## 确认结果（2026-09-09 实施闭合）

数据层/单测（`pnpm --filter @bilibili-downloader/server test`，TEST_DATABASE_URL=pgvector:pg17@55432，104/104 通过）：

- T1（会话生命周期）：数据层通过——`tests/database/chat.test.ts` 7 用例（创建/倒序列表/删除级联/消息顺序与字段/标题更新/404 语义）；重启回看由消息持久化断言支撑。前端交互级验证待用户部署后确认。
- T4（兜底）：服务端实现为"命中为空 → 固定兜底文案、不调用生成"（确定性代码路径，`chat.service.ts finishFallback`），结构性保证不编造；联网真实检索验证待用户部署确认。
- T7（模型来源）：代码级通过——`createQwenClient()` 仅读 `app_settings` 的 `llm.apiKey/llm.modelName` + `QWEN_VISION_PROXY_URL`，无新增模型配置项。
- T8（照片不入知识库）：代码级通过——照片仅写 `message.photo_urls` 与 COS `user-photos/`，无任何写 `summary/`/`summary_segment` 路径。

运行级（本地 server 连测试库，2026-09-09 curl 实测，见 `docs/logs/2026-09-09-rag-chat.md`）：

- T1 部分：创建会话 ✓；列表倒序 ✓；删除（404 后再删/再访问均 404）✓。
- T3 部分（照片链路）：2000×1500 JPEG 上传 → 压缩为 1600×1200 JPEG（`PHOTO_MAX_EDGE=1600`）→ COS `user-photos/1/` 专属目录 → 公网 HEAD 200 / `image/jpeg` ✓；不支持格式（gif/octet-stream）400 ✓（service 单测覆盖）。
- T6（降级语义）：缺 `llm.apiKey/llm.modelName` → 503 明确提示，且配置预检在落库前（重试不产生残留消息，实测）✓；400 空消息 ✓；404 会话不存在（messages/delete）✓。
- "不应发生"抽查：删除后消息不可再访问（级联，DB 断言）✓。
